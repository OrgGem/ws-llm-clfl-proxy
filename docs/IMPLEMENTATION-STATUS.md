# Implementation and release evidence

Date: 2026-10-17. Implementation: five GPT-6 Luna agents at max reasoning, coordinated in the shared repository; independent review: GPT-6 Sol.

## Implemented

- Identity Worker: configured external OIDC client with PKCE/state/nonce and ID-token signature verification, stable principal allowlist, confidential client credentials, public pairing, rotating hashed refresh credentials, live session/client/user/project checks, project and client model permissions.
- AES-256-GCM envelopes with authenticated ownership/provider/expiry/key version; D1 stores metadata and revocation state only. Keys are Worker Secrets; local adapter stores the envelope privately.
- Private `IdentityInternal` WorkerEntrypoint Service Binding; public internal routes are denied. Gateway has no D1 or private signing-key binding in its deployment configuration.
- Gateway protocol v1 multiplexing, sequenced chunks, cancellation, token expiry, hard project/session limits, ACK credit, upstream read limits, and an absolute 8 MiB cumulative serialized output cap per socket. OpenAI and Anthropic endpoints are fixed, redirects rejected, Gateway never retries.
- Loopback HTTP adapter with local bearer authentication and Host/Origin checks; models/chat completions, text/tool calls/provider usage, interrupted-stream errors, SSE backpressure, explicit attempt boundaries, bootstrap/pairing CLI, and distributable bundled CLI.
- Five-screen admin UI, projects and members, limits, client creation/rotation/revoke, credential encryption/revoke/connection test, safe bootstrap download, sessions, stable allowlist approval and key-version/audit display.
- CI, repeatable local key setup, setup skill, migrations, and real-benchmark harness with a one-socket guard.

## Responses and complete generation streaming — 2026-10-18

Adapter 0.3.0 adds independent native `POST /v1/responses` and legacy `POST /v1/completions` contracts alongside Chat Completions. All three support streaming SSE and buffered JSON. OpenAI-protocol/custom providers use fixed native endpoint suffixes through an optional closed WebSocket `api` enum; omitted `api` retains the old chat behavior. Anthropic retains Chat Completions conversion and explicitly rejects the two native OpenAI-only operations. A custom provider must implement the selected endpoint; no API fallback or automatic retry is performed.

Responses preserves typed text, function-call arguments, reasoning, output items, usage and incomplete details. It is stateless at both adapter and direct-WS boundaries: storage/background generation and remote context handles are rejected, and `store:false` is sent upstream. Completed/incomplete terminals are held until Gateway completion; provider error bodies, malformed lifecycle/IDs/sequences, missing sentinels and transport errors cannot become successful terminal events. Chat supports up to eight OpenAI choices, detailed usage, logprobs, refusals, reasoning text and legacy/function-tool deltas. Legacy supports text/token prompt arrays, bounded choices and logprobs; `best_of>1` is rejected because upstream is always streamed. OpenAI usage is requested upstream even for buffered calls, while local streaming usage remains opt-in. Normal `usage:null` chunks are covered by regressions.

## Agent template, generation CLI and environment runtime — 2026-10-18

Adapter 0.5.0 adds `request --api chat.completions|responses|completions --input FILE|-`, using the existing ephemeral loopback adapter and authenticated GatewayClient. It defaults an omitted model only when exactly one local alias exists, emits JSON/SSE to stdout, and returns nonzero for HTTP, stream, incomplete Responses, output and cancellation failures. Input/output are bounded, stdout follows write callbacks and backpressure, and delayed output errors after cancellation are contained. No tool execution or implicit retry is added. One-shot SIGINT aborts generation through request cancellation or closure of its owned WebSocket session; persistent serving retains per-request cancellation.

Explicit `WS_PROXY_CONFIG_SOURCE=env` supports confidential runtimes with Identity/Gateway URLs, client ID/secret, local bearer, a protected envelope file, and one provider/protocol/model alias. State stays in memory. `--config-env` reads bounded, owner-only files from checked handles, uses Node dotenv parsing without shell execution, accepts only documented keys, and preserves inherited environment precedence. Existing pairing/config-file workflows remain available for public clients. Environment mode does not persist or manage provider OAuth refresh tokens; existing paired OAuth profiles continue through the file-backed workflow.

The copyable `templates/ws-llm-agent/` includes an executable bounded task launcher, separate system instructions, `.env.example`, JSON examples and agent guidance.
